# L3 岛屿优化指令（运行时注入；预算门禁已在 tester 强制）

## 铁律（违反 = 锁存器硬错误或 TB 回退，前几轮的血泪）
1. 写使能只加在 always_ff 的时钟更新（`else if (we) cur <= nxt;`）；
   always_comb 的 nxt 必须每拍无条件全量默认赋值 + 条件覆盖。
2. 循环变量一律块作用域 `for (int i = ...)`，模块级 integer 一个不留。
3. 数组一律打包形式（`[N-1:0][W-1:0]`），禁止未打包数组。
4. 每完成一小步就自测：TB 全量 + synthesis_gate；一次只动一个模块。
5. 端口/模块/文件名不改；dbg_* 语义不变；TB PASS + 门禁过 + 双预算达标才收工。

## 当前冠军（必须超越的线）
- 全设计：面积 215,820 µm² / 功耗 21.8 mW（本岛预算更紧，达标线见 tester 报告）
- 每模块面积基线：PRF 67.2k | rename 26.0k | commit 18.3k | BP 17.8k | dcache 18.3k |
  icache 13.7k | IQ 21.0k | ROB 19.0k | LSU 4.7k | EX 5.3k | IF 3.5k | id 0.4k | top 0.7k

## 本岛侧重：cache 与 BP 的存储容量/位宽
1. icache 8→4 行（[3:0] 索引）：代价是冲突 miss。TB 基准 cycle budget 会把关——
   若超时/超预算立即回退本项。
2. dcache 8→4 行：同上。
3. tag 位宽收窄：TB 的 imem/dmem 只有 12 位地址空间（4KB/1K words），
   dcache tag 现为 [23:0] → 可减到 [7:0]（addr[11:4] 为 tag 8 位）；icache 同理。
   预期两项合计 -3~5k。
4. branch_predictor 17.8k：BTB 表项 16→8、BHT 索引位宽减 1；误预测率上升由
   cycle budget 把关。预期 -4~6k。
5. 若 1/2 触发回退，只保留 3/4。
注意：预算 area<190000 且 power<0.020。

## 岛 A 迁移的冠军与教训（HOF，2026-11-04）
- 新冠军：面积 215,237 µm² / 功耗 17.0 mW（功耗已 <0.020 达标；面积是本岛唯一要攻的）
- 教训1：cache 行数 8→4 会挂教师 TB 的 cache_line_conflict 检查（L1 冲突替换规格）
  ——行数保持 8，禁止再减。
- 教训2：任何改动若引起 t02_alu_r 等功能回归立即回退该改动。
- 教训3：面积真实下限约 195k（合法手段）；目标 190k 需要靠 tag 位宽收窄 + BP 缩容这类
  "不减容量、只减位宽/表项"的手段。
