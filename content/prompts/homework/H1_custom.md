实现单模块、低面积、低功耗、可综合的 SystemVerilog AES-128 加密核模块 aes128（FIPS-197，仅加密，不做解密）。最终回答只允许包含该模块的 RTL 源码；不要输出 Markdown、解释文字、推导过程、testbench 或任何其他模块。

接口必须与下列定义完全一致（不得修改端口名称、位宽或方向）：

module aes128 (
    input  logic         clk,
    input  logic         rst_n,
    input  logic         start,
    input  logic [127:0] key,
    input  logic [127:0] plaintext,
    output logic         ready,
    output logic         done,
    output logic [127:0] ciphertext
);

一、字节序与状态矩阵（正确性第一优先级）
1. key、plaintext、ciphertext 都是 128-bit FIPS-197 大端向量：最左侧字节是 byte 0，对应 [127:120]；byte i 对应位切片 [127-8*i -: 8]。
2. AES 状态矩阵按列优先装载：state[r][c] = 输入的 byte[4*c+r]。例如 plaintext = 00112233445566778899aabbccddeeff 时，state[0][0]=8'h00、state[1][0]=8'h11、state[2][0]=8'h22、state[3][0]=8'h33、state[0][1]=8'h44。
3. 输出按同一约定打包：ciphertext 的 byte 0 位于 [127:120]，与输入顺序一致，不得交换字节序。
4. 轮密钥字按大端解释：w0 = key[127:96]、w1 = key[95:64]、w2 = key[63:32]、w3 = key[31:0]。

二、协议与复位（本节为时序约束，规定复位、握手与延迟的时间行为，必须逐条满足；教师 TB 使用 === / !== 精确比较逐项检查，任何信号出现 X 或 Z 即判失败）
1. rst_n 是同步低有效复位：只在 clk 上升沿生效；某上升沿采样到 rst_n=0 时清空全部内部状态、使 done=0 并把 ready 置 1；rst_n 在两个上升沿之间变化时，所有寄存器输出保持原值。禁止 posedge clk or negedge rst_n 等异步复位写法。
2. 复位生效不要求等待释放：rst_n=0 经过第一个上升沿之后，ready 就必须为 1、done 必须为 0。ready 的复位值是 1。
3. start && ready 在 clk 上升沿成立时，锁存 key 与 plaintext 开始一次加密；key/plaintext 只在该沿采样一次，之后输入端变化不得影响本次加密结果。从该沿的下一拍起 ready=0，忙碌期间必须忽略新的 start。
4. start 之后的第一个上升沿 done 必须为 0：禁止组合逻辑在接收当拍就完成加密。
5. 加密完成后 done 恰好拉高一个时钟周期，该拍 ciphertext 有效且 ready=0；done 结束后的下一个上升沿起 done=0、ready=1，并能立刻接受下一次 start（支持背靠背加密，无额外气泡）。
6. 从采样 start 的上升沿（不含该沿）到 done 为高的上升沿（含该沿），延迟最多 200 个时钟周期。
7. done=0 时 ciphertext 可为任意值；done=1 期间 ciphertext 必须稳定。
8. 忙时复位：加密进行中采样到 rst_n=0 时，立即中止本次加密并彻底清空全部状态（包括轮密钥、轮计数、列计数与完成标志）；复位释放后 ready 恢复为 1，随后发起的任意新加密必须结果完整正确，不受中止影响。

三、算法（标准 FIPS-197 加密）
1. 初始轮：state = plaintext XOR {w0,w1,w2,w3}。第 1–9 轮：SubBytes → ShiftRows → MixColumns → AddRoundKey(w[4r..4r+3])。第 10 轮：SubBytes → ShiftRows → AddRoundKey，不做 MixColumns。
2. SubBytes 使用标准 AES S-box，查表实现必须与下表逐字节一致（行 = 字节高 4 位，列 = 低 4 位）：

3. ShiftRows：state'[r][c] = state[r][(c + r) mod 4]，第 r 行循环左移 r 字节。
4. MixColumns：每列左乘矩阵 [[2,3,1,1],[1,2,3,1],[1,1,2,3],[3,1,1,2]]；乘 2 与乘 3 用 GF(2^8) 的 xtime（模多项式 x^8+x^4+x^3+x+1，即 0x11b）级联实现。
5. 密钥扩展按 FIPS-197 生成 w[0..43]：w[i] = w[i-4] XOR temp；当 i%4==0 时 temp = SubWord(RotWord(w[i-1])) XOR Rcon[i/4]，Rcon[1..10] = 01,02,04,08,10,20,40,80,1b,36；其余 temp = w[i-1]。

五、生成前请在内部按顺序完成以下推导，但不要把推导过程输出到最终回答：
1. 微架构选型（先选型，后写码）：自行设计并比较至少两种候选数据通路。设计空间包括但不限于：按字节还是按列为处理单位、共享 2 个还是 4 个 S-box、密钥扩展独立成拍还是与列处理交错。对每种候选在内部推算两个指标：①总拍数 = 每轮拍数 × 10 轮 + 装载/完成开销（依据：全程约 200 次 S-box 查找，数据 160 次 + 密钥扩展 40 次，S-box 实例数决定每拍最多完成几次查找；注意只装 1 个 S-box 时总拍数必然超过 200 上限）；②状态寄存器每位在整个流程中需要从几个来源写回——来源越多，写回端多路选择器网络越大，组合面积越大。选型准则（依次判断）：总拍数 < 200 且留有不小于 20% 的余量；在满足时限前提下 S-box 实例数尽量少；每个状态位的写回来源不超过 2 个（保持 / 本拍新值）；触发器总数贴近 264 的下限（状态 128 + 密钥 128 + 少量计数与标志）。把候选比较在内部列成小表后选定，选定结果代入第 2 步的统一写回纪律。
2. 统一写回数据通路（无论选哪个方案都必须遵守）：把 SubBytes → ShiftRows → MixColumns → AddRoundKey 折叠成一个“列组合表达式”——每拍根据列号用纯布线取出移位后该列的字节（行移位只是字节重排，不占独立拍），依次完成 S-box、列混合与轮密钥异或后写回该列；状态寄存器的每个位在任意拍只从 {保持, 本拍新值} 二选一，禁止多相位、多来源的写回多路选择器森林。
3. 密钥扩展结构：不预存 11 组轮密钥（那需要约 1.4 kbit 额外触发器）。采用在线扩展：128-bit 密钥寄存器按轮原地更新（w0'=w0 XOR g(w3)，w1'=w1 XOR w0'，w2'=w2 XOR w1'，w3'=w3 XOR w2'），SubWord 复用共享的 S-box 组、与列处理交错进行，不增加独立 S-box 实例（若你的选型确需 1 个专用密钥 S-box，须在第 1 步的对比表中计入其面积代价后再采用）。
4. 寄存器数量最小化：不设独立输出寄存器——done 有效的拍里 ciphertext 直接由 128-bit 状态寄存器给出（只在 done 拍被采样，done=0 的拍取值任意），节省 128 个触发器；ready/done 用单个标志位；轮计数与列计数合并为一个计数器。全设计触发器总数约 264（状态 128 + 密钥 128 + 计数与标志数个）。
